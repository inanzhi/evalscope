1LLM 效果评测集

目标：以较小题量快速评估各供应商模型在「中文知识 + 数理逻辑」两个维度的能力上限，控制调用成本与时间。

数据集选型：文理双维

  • CMMLU：覆盖 67 个中国本土学科，评估中文知识广度。
  • HumanEvalPlus：在 HumanEval 基础上扩充数万条测试用例，评估编程逻辑，经沙盒执行验证代码正确性。

抽样策略：按学科分层截断

  • EvalScope 原生后端将 CMMLU 拆分为 67 个学科子集，--limit 对每个子集单独截断，实现分层均衡。
  • 每科取 50 题，合计 3350 题；固定随机种子保证可复现，无需文件操作，学科权重保持不变。
  • HumanEvalPlus 仅 164 题、成本较低，保持全量评测，并启用 Docker 沙盒安全执行生成代码。

2VLM 多模态评测集

目标：将 1000~2700 题的多模态测试集压缩至约 500 题，同时保证能力分布与原集一致。

问题与方案

  • 问题：测试集按类别集中排序，框架的 limit 仅取全局前 N 条，可能导致部分类别未被抽样，维度失衡。
  • 方案：读取本地 TSV，按类别列（能力类别 / 任务类型 / 场景，自动探测）做等比例分层抽样（固定随机种子），存回原文件名供框架读取。
  • 可复现：任意机器均抽得完全相同的约 500 题；自动备份全量数据，避免重复抽样导致样本持续缩减。

两种评测模式：分层抽样与全量

  • 分层抽样（默认）：每个集压缩至约 500 题，4 个集合并评测，用于快速生成能力雷达图做横向对比。
  • 指定数据集全量：仅关注个别能力维度时，跳过抽样、对选定数据集跑全量评测，维度最完整，适合定点深测或复核抽样版结论。
两种模式共用同一运行器：抽样为评测前对 TSV 的预处理步骤，全量评测仅需省略该步骤，命令本身不变。

3单轮长文本性能压测

目标：横向对比商业 API 的长上下文推理性能，核心指标为首字延迟（TTFT）与生成速度（TPOT）。

三项公平性设计

  • 数据集采用 longalpaca：真实长文本（>6000 token）。不采用 random，因无意义字符会触发模型立即 EOS，导致 TPOT 失真。
  • 防服务端缓存命中干扰：并发梯队间游标自增不重复，并以偏移量错开历史，杜绝 KV / Prefix Cache 命中影响 TTFT。
  • 对齐生成长度：商业 API 不支持忽略结束符，以统一的最大输出 token 上限截断，保证 TPOT 可比。

压测梯队设计

  • 并发梯队 1 / 8 / 16：分别测量单点极限速度、并发吞吐、极限吞吐，各梯队对应请求量 20 / 80 / 160。
  • 开启流式：以精确捕获 TTFT。预热 2 条：排除冷启动延迟，不计入报告。
  • 全程发送约 262 条互不重复的请求；预热数据同样取自数据集并消耗游标，确保全程语料新鲜，杜绝缓存命中干扰。

关键指标（对比时仅看归一化值）

指标含义
TTFT首字延迟，衡量长 Prompt 的 Prefill 速度（关注 P50 / P99）
TPOT(总延迟−TTFT) / 输出 token，剔除输出长短影响，最公平的生成速度指标
RPS / TPS高并发下的吞吐量与算力水位
不直接对比端到端总延迟，因其受各模型输出长短影响较大。应核对平均输出 token 是否均在 500 左右，确认截断生效、对比基础公平。

定时自动化与归档

  • 定时调度：通过本地定时调度智能体创建 3 个每日任务（21:00 / 04:00 / 15:00），到点各执行一轮，时间戳天然隔离、互不覆盖。
  • 自动归档：每轮完成后自动定位最新结果目录，按 parallel=1 / 8 / 16 三档提取 TTFT、TPOT（P50 / P99）、RPS、TPS 及成功 / 失败数，沉淀为 notes/perf-commercial-apis/runs/<日期>_<时间>_<profile>.md。
  • 三档共用同批数据：数据游标固定（offset=500）；三次间隔 6~11 小时，服务端前缀缓存已过期，用同批数据便于跨时段直接对比。
前置条件：API Key 须配置为持久环境变量（DASHSCOPE_API_KEY，腾讯云另需 TENCENT_API_KEY），否则定时任务无法取得凭证。

4多轮对话 KV 缓存命中率压测

目标：评估服务端在多轮对话中对历史上下文（Prefix Cache）的复用能力，这是多轮场景降本提速的关键。

两个核心指标

指标口径意义
Cache Hit (%)命中 token ÷ 全部输入 token，按 token 总量加权（含第 1 轮 0%）实际节省的成本与算力
Eligible Cache Hit Rate剔除第 1 轮与本轮新内容后的命中率服务端缓存系统的实际复用能力
数据真伪判别：Eligible 恒为 100.00 表示服务端未回传真实数据、为客户端理论估算值；出现 93.00 等非整数则为真实命中数据。

三项对齐机制（保证跨厂商公平）

  • 数据集预生成：脚本一次性生成固定的多轮对话（基于 swe_smith，呈「长首轮 + 尾部增量」结构，贴近 Agent 场景），随机性固化于文件，所有厂商使用同一份数据。
  • 会话隔离：腾讯云须开启会话缓存开关并自动注入会话标识；阿里百炼为隐式缓存，无需此参数。
  • 防复测污染：同模型同厂商重测时，从大数据池按偏移量取不相交子集，避免残留缓存使冷启动命中率虚高。
统一原则：控制变量 · 公平对齐 · 结果可复现。效果评测侧重分层均衡与低成本评估，性能压测侧重杜绝缓存命中干扰与指标归一化。
